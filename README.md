# Harish V — portfolio

Personal site for Harish V ([ZeonArc](https://github.com/ZeonArc)), a full-stack developer and B.Tech CSE student at SRMIST Trichy. Built with Next.js 16 (App Router), React 19, Tailwind CSS 4, shadcn/ui (Radix), Motion and Lenis.

**Design.** The visual language is borrowed from control-room *mimic panels*: flat plates, hairline seams, and indicator lamps. One lamp colour means "active, selected or available". Every project is drawn as a schematic of its real architecture, and the node colours mean something: blue is interface, sage is data, ink is services, and dashed boxes are outside services. Type is Big Shoulders (names), IBM Plex Sans (text) and IBM Plex Mono (anything counted or identified). There is no glow, glass, gradient or 3D, and motion is limited to small reveals and a signal that runs along a project's wires on hover.

## Quick start

```bash
npm install
cp .env.example .env.local   # optional for local dev
npm run dev                  # http://localhost:3000
```

| Script | What it does |
| --- | --- |
| `npm run dev` | Dev server (Turbopack) |
| `npm run build` / `npm start` | Production build / serve it |
| `npm run check` | Route types + TypeScript + ESLint |
| `npm run resume` | Rebuilds `public/resume.pdf` (one A4 page) from the content files |

## Editing content

Everything personal lives in **`src/content/`**; you shouldn't need to touch component code.

| File | Controls |
| --- | --- |
| `site.ts` | Name, role, headline, résumé summary, location/time zone, availability, email, socials, bio, SEO |
| `projects.ts` | Projects, categories, featured flags, architecture diagrams and write-ups (problem / how it works / where it stands / spec) |
| `skills.ts` | The Stack section, grouped by layer. No ratings: each tool lists the projects whose `tags` include it |
| `experience.ts` | Jobs and internships. The section and its nav link stay hidden while the list is empty |
| `education.ts` | Degree and certifications |
| `navigation.ts` | Section order and which sections appear in the navbar |

After changing content, run `npm run resume` so the PDF matches. The content files avoid `@/` imports so the résumé script can load them directly with Node.

### Adding a project

Add one object to `projects` in `src/content/projects.ts`. The `diagram` is optional:

```ts
diagram: {
  nodes: [
    { id: "web", label: "Web app", detail: "Next.js", layer: "client", col: 0, row: 0 },
    { id: "api", label: "API", detail: "Express", layer: "service", col: 1, row: 0 },
    { id: "db", label: "Postgres", detail: "Prisma", layer: "data", col: 2, row: 0 },
  ],
  edges: [
    { from: "web", to: "api", label: "REST" },
    { from: "api", to: "db" },
  ],
},
```

`col` runs with the flow (left to right) and `row` runs across it. Keep labels to about 13 characters and details to about 20. Diagrams in the two-column grid read best with 3 columns or fewer; featured projects can use 4. On phones, the same diagram is redrawn top to bottom automatically. Projects without a diagram show their spec table instead.

### Photo and résumé

- `src/content/images/profile.webp`: the hero portrait (4:5). It's statically imported, so `next/image` produces srcsets and a blur placeholder.
- `public/resume.pdf`: generated by `npm run resume`. Drop in your own PDF to replace it.

## Environment

See `.env.example`. Everything is optional in development.

| Variable | Purpose |
| --- | --- |
| `NEXT_PUBLIC_SITE_URL` | Canonical URL for metadata, sitemap, Open Graph and JSON-LD (falls back to Vercel's production URL) |
| `RESEND_API_KEY` | Sends contact-form email through [Resend](https://resend.com). Without it, dev logs messages to the server console and production replies with a clear "not configured" error |
| `CONTACT_TO_EMAIL` / `CONTACT_FROM_EMAIL` | Recipient inbox, and a sender on a domain you've verified in Resend |
| `GITHUB_USERNAME` / `GITHUB_TOKEN` | Contribution graph in About (refreshed every 12h). Defaults to `site.githubUsername`; if the data can't be fetched, the graph is hidden rather than faked |

## Deploy

Push to GitHub and import the repo on [Vercel](https://vercel.com/new), then add the environment variables above. Vercel Analytics and Speed Insights switch on automatically there (they're only rendered when `VERCEL` is set).


## Accessibility and performance

- Semantic landmarks, one `h1` per page, a skip link, and focus moved to sections on in-page navigation.
- Every schematic has a text alternative that lists its parts and connections.
- Visible focus rings, `aria-pressed` filters, and a keyboard-driven ⌘K palette.
- `prefers-reduced-motion` turns off smooth scrolling, reveals and the wire animation.
- Scroll reveals are plain CSS toggled by one shared `IntersectionObserver`, so nothing waits for hydration.
- Lenis, motion (mobile menu), cmdk, sonner, the write-up modal and the contact form's validation code are all code-split.
- Each section is wrapped in `<Suspense>` in `app/page.tsx`. The page is fully prerendered; the boundaries let React hydrate one section at a time.
